ABSTRACT CLASS
So,
 
what
 
is
 
the
 
difference between
 
an abstract
 
class
 
and
 
a
 
regular
 
class?
 
 
Here’s the difference – “
An abstract class CANNOT be instantiated directly
.” It needs to be extended to a subclass, implement all abstract methods in that subclass, and then instantiate the subclass. Also, the subclass should NOT be declared as an Abstract class.
This means that the ‘Vehicle’ class declared above, as an Abstract class, cannot be directly 
instantiated.
You will get an error if you try to create an object of this ‘Vehicle’ class.

Why do you need an abstract class?
The
 
answer
 
is
 
that
 
you
 
can
 
use
 
an
 
abstract
 
class
 
to
 
share
 
the
 
code
 
with
 
other
 
classes
 
that
 
share similar
 
behavior.
 
In
 
our
 
earlier
 
example,
 
we
 
used
 
the
 
‘Vehicle’
 
class,

will

However,
 
there
 
are
 
some
 
common
 
behaviors
 
that
 
all
 
vehicles
 
share.
 
They all – start, stop, move, accelerate, decelerate, apply breaks.
If you want to make sure that all child classes of vehicle implement at least these behaviors, then you can declare the parent class (Vehicle) as ‘abstract’ and add these abstract method declarations to it. Now, whenever this ‘Vehicle’ class is extended into, say – ‘Car,’ ‘Bike,’ ‘Boat,’ etc., all those child classes will be required to implement these behaviors.

INTERFACE
An Interface is similar to an Abstract class, but there are some differences. An Abstract class can have a mix of abstract and non-abstract methods (methods with and without implementation), whereas an Interface must have 
all abstract 
methods. You cannot declare a method with a body in an Interface. Here is an example of an ‘Interface’
package
 
abstractClassNInterface
;
public
 
interface
 
Vehicle_Interface
 
{
void
 
start(); 
void 
stop(); 
void 
move();
void 
accelerate(); 
void 
decelerate(); 
void
 
applyBreaks
();
}
